# claude/worker-ux-highlights-layout-2phg4l

**Intent:** Put the symbol of the AI tool that made an annotation at the end of every highlighted text in every view, and fix the crowded, glitchy split views: a pane header per pane, tool cards collapsed to their symbols by default, and, when a tray tab opens, a strip that scrolls sideways between the two full-width panes and the tray instead of squeezing the panes — for Side by Side and Top and Bottom both.

**Files:**
- `src/components/reader/block-view.tsx` — the tool chip and the comment chip share one style (`MARK_CHIP`) that sits on the highlight's bottom edge at the end of the text; the figure, table, and equation side label shows the tool's symbol instead of the color dot when the annotation is a tool's.
- `src/components/reader/reader-interactions.tsx` — the tool symbol attaches to every stored AI annotation, not only in a narrow reader; `split` and `paneHeader` props; a split pane counts as narrow (`applyNarrow`, one callback shared by the resize observer and a `split` effect), so stored cards collapse and new ones dock below the highlight; the root is a flex column: in a split view a pane header row (the document select, the article menu and search, Distill) above the scroller, the floating menu strip and the sticky Distill only in Normal view; no edit hint in a split pane.
- `src/components/reader/reader-panes.tsx` — `viewHref` (one URL builder for the views), `PANE_HEADER` (the header row's classes), `PaneDocumentSelect` (each pane's document, chosen in its header; replaces the select that floated over the second pane's text); the pane wrappers are flex columns; `--reader-cut` per view (the strip's cut in Top and Bottom, 0 in Side by Side).
- `src/components/reader/workspace.tsx` — `readerView` prop; the grid column is `minmax(0, 1fr)` and the row `min-w-0`, so a pane's widest line can never push the rail off screen; the strip: the reader and the tray column in one scroller (`.reader-strip`) in a split view, `revealTray` on every tab open and jump, the fold that scrolls back before the column closes, `--strip-cut` and the `strip-scrolling` class from the scroll position, the edge buttons, and the reset to the documents on mount.
- `src/components/video/video-pane.tsx` — `paneHeader` prop rendered in the same header row; the media column uses `.reader-column` with its own `--reader-column-w`, so it follows the cut too.
- `src/app/n/[notebookId]/page.tsx` — passes `readerView` to the workspace, and `split` and `paneHeader` (a `PaneDocumentSelect` per pane) to the reader and the video pane; the pane node is a flex column with `min-w-0`.
- `src/app/globals.css` — `.mark-chip`; `.reader-column` centers in the visible part (`--reader-cut`); `.pane-header` padding follows the cut; `.reader-strip` (md+: sideways scroll, mandatory snap, contained overscroll, no scrollbar) and its children's snap alignment; `.strip-scrolling` turns the column and header transitions off while the strip moves.
- `src/lib/i18n/dict/panes.ts` — `paneDocument`, `paneDocumentTitle`, `stripToTray`, `stripToDocuments` (en and zh); `secondPaneDocument` removed with the floating select.
- `SPEC.md` §6 — the reader views and the split-view layout; the mark symbol's place.

**Decisions:**
- The tool symbol shows in every view, not only in a narrow reader: the user asked for it on every highlight. Its place is the end of the highlighted text, on the bottom edge (a 15px chip, `vertical-align: -0.22em`, a paper ring), never over a letter. Plain color highlights carry no symbol (their color is the mark); comments keep the comment bubble in the same chip style; link chains keep their own chip.
- "Collapsed by default" in a split pane is the existing narrow-reader mode forced on: a split pane never opens a stored card beside the article, and stored cards close when a pane becomes a split pane. Output that is streaming or unsaved still opens, as before.
- The strip keeps the reader at exactly the width it has with the tray folded, so the two panes fill the browser and the tray adds to the right; the tray keeps the reader's chosen width (the resize bar still works) rather than becoming a full screen of its own. With mandatory snap there are two rests: the documents, or the tray with the second pane and a peek of the first. The strip starts on the documents on load and on entering a split view; only a tab open, a jump to a note or an annotation, or the edge button scrolls to the tray.
- Top and Bottom gets the same strip (the user asked for both modes). Its panes are full width, so the article column and the pane header re-center in the visible part and no line starts under the edge; in Side by Side the panes are narrower than the column, so the first pane peeks instead.
- Folding the tray in a split view keeps the column's width (an inline width) while the strip scrolls back, then closes it, so the tray slides out instead of jumping; opening skips the width transition and lets the scroll be the motion. Normal view is untouched: the same row, the same width transition.
- The pane header holds the document select for both panes, not only the second, so a pane's document changes in place; the top bar's document pill still drives the first pane. Distill moved from a sticky pill over the text to the header's end in split views; the article menu's dropdown and the search bubble drop below the header.
- The strip resets to the documents in the workspace effect because the pending queue's focused card calls `scrollIntoView` as it mounts, which scrolled the tray into view on every load; child effects run first, so the reset wins. A later focus move (j/k in the queue) still reveals the tray, which is right.
- The grid fix (`minmax(0, 1fr)`, `min-w-0`) is the cause of the clipped panes in the user's screenshot: a long unbreakable line inflated the auto column past the browser and pushed the rail and the header's right controls off screen. Verified with a 200-character unbroken URL in a seeded paragraph: the page stays the viewport's width.
- Pre-existing, not changed: in Normal view the Explain card can overlap the article's right edge when the gutter is between 140 and 284px (the card floor is 260px).
- Verified in headless Chromium against a local Postgres (pgvector via apt) with a seeded project of two documents and highlight, comment, Explain, Simplify, and assistant annotations, at 1440×900 and 1280×760: Normal, Side by Side, Top and Bottom; tray folded and open; the strip's two rests and the edge buttons; the fold from the tray; a tool chip opening its card in both views; the pane menu dropdown; no console errors. `tsc`, `eslint`, and `next build` pass. No new dependencies.
