# claude/pdf-handwriting-import-format-0trmcq

**Intent:** Every assistant chat (the reader's selection-popover/article-menu chat, the video pane's Assistant chat, and the side-panel Assistant's Ask) gets a way to stop a turn mid-flight — the Send/Ask/Run button becomes a Stop control while a turn is running, and the request aborts server-side too.

**Files:**
- `src/components/reader/reader-interactions.tsx` — `assistantTurn` takes an optional `AbortSignal`; a shared `chatAbortRef` is used by `runAssistant` (the popover's "ai" submenu, before the chat card exists), `sendChatMessage`, and `openArticleChat`'s first turn. New `stopAssistantChat()` aborts and clears busy state; wired to the Run/Send buttons (icon swaps to `StopIcon`, matching the existing voice-button pattern) and to `closeAssistantChat()`/Escape (closing the card stops a running turn too, since nobody will read the reply). `LoadingDots` import dropped — no longer used once the Run button's busy state became a Stop icon instead of a spinner.
- `src/components/video/assistant-card.tsx` (`MediaAssistant`) — same pattern: `sendAbortRef`, `stopSend()`, wired to the Send button and the card's ✕ close button. `runSkill` (the Formalize chips) is untouched — it's a one-off document rewrite, not the chat turn.
- `src/components/assistant/assistant-panel.tsx` — `ask()` genuinely streams (unlike the other two, which are single-JSON replies), so Stop here ends the read loop and *keeps* whatever text already streamed in rather than discarding it. `runTask` (Contradictions/Gaps/Unsourced) and `generateRecommended` (the Summary depths) are untouched — neither is the chat.
- `src/app/api/assistant/act/route.ts`, `src/app/api/assistant/route.ts` — both pass `abortSignal: req.signal` into their model calls now (`callForJson` already accepted it; `streamText` does too), matching the DISTILL/FORMALIZE precedent in `/api/derive/route.ts` — a client-side Stop actually halts generation server-side, not just the client's read of it.
- `src/lib/i18n/dict/{reader,video,assistant}.ts` — one new key per surface (`stopAssistant` ×2, `stopAsk`), en+zh.
- `SPEC.md` — §6, §7, §11 each note Stop where they already describe that chat.

**Decisions:**
- Scoped to genuine "chat" surfaces only (multi-turn or ask-and-reply conversational UI). Left out: Distill (already has its own Cancel, and isn't a chat — one question, a fixed set of quotes), Circle & ask on handwritten pages (single Q&A, not a chat, per `page-block.tsx`'s own `Answer` type being one object not a message array), the side panel's Contradictions/Gaps/Unsourced tasks and Summary depth generation (both single-shot report/document actions, not conversational).
- Visible button content on Stop is an icon (`StopIcon`), not text — matches the existing voice-toggle button in the same reader chat card (icon swaps with state, `aria-label`/`title` carry the description) rather than Distill's separate "Cancel" pill, since these are compact inline chat-input rows, not a full-page ask view.
- On abort, nothing is appended to the conversation history (no synthetic "stopped" message) — a stopped turn just never gets a reply, so a future turn's `history` never carries a confusing placeholder back to the model.
