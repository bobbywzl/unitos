# claude/unitos-import-comparison-xraic7

**Intent:** Add the `/importcompare` agentic loop (headless-Chromium capture of the original and the Unitos import, vision comparison of every complex element and the layout, central fixes in the parse pipeline), an explicit PDF import pick in the upload assistant (judge automatically / pages as they are / pages + convert to text), a KaTeX verify-and-repair step in handwriting conversion ported from notes2latex, Claude Fable 5.1 on every upload and parse model call, and the two parse fixes the first loop round found.

**Files:**
- `.claude/commands/importcompare.md` — the slash command: stand up the app, pick sources, capture, compare with the model's own vision (structural census first, element pairs second, layout third), strict report shape, fix rules (general pattern only, anchoring invariant, PARSER_VERSION bump), iterate, collectors as subagents.
- `scripts/qa/import-compare.mjs` — the capture tool the command drives: ingests through `/api/documents`, screenshots the original (full page + one crop per table, math, figure, gif, video, embed, svg, code, list) and the reader (full page + one crop per TABLE/EQUATION/FIGURE/CODE/LIST block), fetches the raw HTML with the parser's UA to tell client-rendered elements from parser misses, renders PDF pages with unpdf, measures layout on both sides (column, margins, text and heading sizes, paragraph gap, toc, widths as a share of the column), pairs by content key (TeX, image basename, opening text) then by order, records why an image failed to load, writes `report.md` + `manifest.json` per source under `.qa/`. Behind a proxy it probes and falls back to `--ssl-version-max=tls1.2` when the proxy resets Chromium's TLS 1.3 hello; never disables verification.
- `.claude/skills/unitoscompareloop/SKILL.md` — one line pointing the text-census loop at the visual round.
- `.gitignore` — `.qa/` (capture runs).
- `src/lib/derive/config.ts` — `PARSE_MODEL = "claude-fable-5-1"`; `UPLOAD_MODEL`, `CLASSIFY_MODEL`, `CONVERT_MODEL` read it. `src/lib/parse/structure.ts` — the core and structure passes use `PARSE_MODEL`. `src/lib/usage.ts` — exact price row for `claude-fable-5-1`. `SPEC.md` §2 — the model note.
- `src/components/reader/upload-assistant.tsx` — the PDF import pick: three pills (judge automatically, pages as they are, pages + convert to text) with one note line; an explicit pick sets the `pages`/`convert` directives outright, no model call; judge keeps the instruction check's reading. `src/lib/i18n/dict/panes.ts` (en + zh keys, the PDF nuance line), `src/lib/i18n/dict/works.ts` (guide copy), `SPEC.md` §15 and §16.
- `src/lib/katex.ts` — `KATEX_MACROS` (`\mbox`, `\hbox`, `\textnormal` → `\text`) shared by the reader and the verifier, and `texError` (KaTeX strict parse). `src/components/reader/equation.tsx` renders with the macros.
- `src/lib/handwritten/convert.ts` — after the batches, `repairEquations`: every EQUATION block is parsed with KaTeX; the failures go back to the model once with the parser's error (`src/lib/prompts/fix-tex.ts`); a fix that parses replaces the text, anything else stays as written. Best effort, never fails the run. `src/lib/prompts/convert.ts` — three reading rules from notes2latex (crossed-out text is deleted, corrections in another ink win, margin notes land in reading order; an ambiguous symbol takes the standard reading) and EQUATION TeX restricted to what KaTeX renders.
- `src/lib/parse/url.ts` — MediaWiki `{\displaystyle …}` unwrapped only as whole brace groups (position-based stripping left unbalanced TeX, 4 of 48 equations on the Matrix page failed KaTeX); inline MediaWiki math becomes the MathML's glyph text instead of raw TeX in prose and table cells. `src/lib/parse/types.ts` — `PARSER_VERSION` 11.

**Decisions:**
- The "AI computer vision" is the model's own Read of PNG crops, in the session and in subagents — no CV library, no extra key. Pixel diffing was rejected on purpose: fonts, widths and theme differ by design, so the comparison is structural (census), then semantic per element pair, then proportional (layout).
- The loop runs without `ANTHROPIC_API_KEY`, so it tests the mechanical parser; the core and structure passes that drop chrome are off, and chrome findings are expected in that mode.
- handwriting-ocr (Breta01, TensorFlow 1.x, 2018) was not ported: it recognizes Latin words only, no math, needs a Python service and trained models, and the existing vision-model conversion already exceeds it. notes2latex's ideas were ported instead of its Python (LiteLLM + latexmk + LangGraph): KaTeX is the compiler, the prompt rules carry over, page batches stay parallel (its sequential context carry-over trades speed for consistency of one LaTeX document, which Unitos does not produce).
- No server-side refusal fallback was added to the Fable 5.1 calls (the AI SDK provider path is untested here without a key); a refused or failed pass already falls back to the mechanical blocks.
- Model ids and prices came from the claude-api reference, not memory.
