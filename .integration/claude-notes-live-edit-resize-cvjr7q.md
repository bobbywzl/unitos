# claude/notes-live-edit-resize-cvjr7q

**Intent:** Three fixes on notes: edits show as the rendered note while editing (each note edits like a small document, not as markdown text), the editing card shows as much of the note as the pane allows, and the tray's note editor can be dragged or popped out into a floating card over the article.

**Files:**
- `src/lib/note-markup.ts` — new: parses a note's markdown into lines of runs (headings, nested lists, quotes, code lines, bold/italic/underline/strike/code, the four colors, `[block id]` chips, links), renders them as the editor's document HTML, and maps source (markdown) offsets to visible offsets and back.
- `src/lib/note-doc.ts` — new: reads any DOM the browser leaves in the editor back into markdown (block elements to lines, inline elements to styles, unknown elements transparent, browser artifacts such as nbsp and zero-width characters cleaned); markers hug the words; italic inside bold takes `_`; adjacent runs with equal styles merge. Selection sentinels are placed by position.
- `src/lib/note-editable.ts` — new: the editable core. The markdown is the model: typed characters, Enter, and the style commands go into the markdown at the caret's source offset and the document is painted from it; deletions, paste, and IME stay native and are read back. Reads the selection through sentinel characters, keeps its own undo/redo (a repaint breaks the browser's), continues lists and quotes on Enter, ends an empty item, splits styled text cleanly, drops a marker on Backspace at a marked line's start (a nested item outdents first), models the typing style (Cmd+B/I/U or the bar with a bare caret styles what is typed next, until the caret moves on its own), toggles a style over a selection by rebuilding the line's runs, and normalizes the text to the serializer's form on every paint.
- `src/components/outline/note-editor.tsx` — the textarea is a contentEditable with the Markdown component's prose classes; the line and color commands still patch the markdown; B/I/U go through the core's `toggleStyle`; Tab/Shift+Tab indent/outdent; `handle` renders a grip row ("Note") as the drag handle; `className` lets the parent cap the height (the text scrolls, the bar stays).
- `src/components/outline/use-note-draft.ts` — new: the auto-save logic moved out of the note card so the tray card and the floating card share it. It also keeps the content from when the editor opened, so Cancel restores it even after a sync refresh replaced the note's content mid-edit.
- `src/components/outline/note-card.tsx` — uses the hook; the editing card caps at the scroll pane's height (the tray's panel, or the window on the notes full page) and scrolls its text inside, and brings itself into view when it opens; in the tray the handle row drags the editor out and a Pop out button floats it; a note that is floating shows a placeholder card with Back to the tray.
- `src/components/outline/floating-note-editor.tsx` — new: the floating card over the article — movable by its handle, resizable from its corner (native handle), kept on screen on resize, docked back by dropping it on the tray or pressing Back to the tray; Save/Cancel/Esc/Cmd+Enter as in the tray.
- `src/components/outline/use-outline.ts` — `FloatingEdit` state and the actions `floatNote`, `floatingDraftChanged` (a ref, so typing never re-renders the workspace), `dockNote(reopen)`; `editRequest` can carry a draft so the tray card reopens on the floating card's text.
- `src/components/reader/workspace.tsx` — renders the floating card outside the tray; docking opens the tray on notes.
- `src/components/outline/notes-tray.tsx`, `src/components/outline/section-item.tsx` — the composers use the same editor.
- `src/lib/i18n/dict/outline.ts` — new keys (en + zh): `noteText`, `popOut`, `popOutTitle`, `dockBack`, `dockBackTitle`, `floatingLabel`, `floatingTitle`, `dragOut`.
- `src/app/globals.css` — `.note-doc` rules: pre-wrap, placeholder, no focus ring (the card's outline marks editing), slim blank lines, code lines, the ¶ chip, links.
- `SPEC.md` — §6 gains the note editor paragraph (document view, sizing, floating card).

**Decisions:**
- The user's follow-up asked for each note to read like a small Google Doc. The editor therefore shows the rendered document (no markers) with the note card's own prose classes, while notes stay markdown in the database — nothing else in the app changes. The old textarea markup toolbar is kept as commands on the markdown.
- Typing is model-driven (characters go into the markdown), because Chrome types at a style boundary with the previous character's style regardless of the caret's DOM position; that made `**word**` typed by hand unreliable. Consequence: after a bold word the caret sits outside the style, so typing there is plain unless Cmd+B is on; clicking at the end of a bold word keeps typing bold. Whitespace typed at a run's edge goes outside the markers.
- One editor line is one block, so a blank line in the markdown is a slim empty paragraph in the editor (still clickable), and consecutive lines are separate paragraphs even though the renderer joins them with soft breaks.
- Painting normalizes the markdown to the serializer's form (for example `1)` becomes `1.`, a stray top-level indent is dropped, a lone `-` is text until its space is typed). A note whose markdown is not in that form is rewritten on its first auto-save; Cancel still restores the original.
- The floating card lives at workspace level (state in `useOutline`) so it survives tray tab switches; its live draft sits in a ref and docking passes it back through `editRequest`. Pop out is offered only in the tray (the notes full page has no article to float over).
- Chrome's `execCommand` is not used at all.
- Validation: `npx tsc --noEmit` and `npx eslint` on the changed files pass. Headless Chromium suites in this session: 20k random well-formed markdown samples round-trip through render → serialize with no visible change and idempotent output; 45 editing scenarios (typing, Enter, lists, quotes, undo/redo, paste, chips, Cmd+B typing style, range toggles, partial unbold, autoformat of typed markdown); and the real app against a local Postgres: editing, sizing (a 40-line note's card fills the tray panel and scrolls inside), pop out, drag, dock back, drag-out, drop on the tray, auto-save after reload, and the notes full page. IME composition is guarded but was not exercised.
