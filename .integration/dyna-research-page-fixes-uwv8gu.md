# claude/dyna-research-page-fixes-uwv8gu

**Intent:** A URL document reads as a replica of its page — masthead, contents list with working links, headings by level, bold and italic runs, figures at the page's proportions and in the page's rows, script-drawn charts rendered in a browser, the page's font — with the parse model reading the page's own HTML to lay it out; the glossary hover text in the reader's language; the upload assistant checking captions against figures; a first-open reveal; the add-document dialog opening on URL.

**Files:**
- `src/lib/parse/url.ts`, `src/lib/parse/dom-text.ts`, `src/lib/parse/structure.ts`, `src/lib/parse/ingest.ts`, `src/lib/parse/types.ts` — the walk keeps a contents nav (label + `contents` list with `targetFragment` links and code spans on the labels), turns contents targets and page-sized paragraphs into headings by level, builds the kicker, metadata line, pull quote, quote, and caption tokens, emits bold/italic/underline/code style spans, prunes the page's hidden tree and footer chrome, reads the page's font; retype and merge carry spans and fragments; `resolveContentsLinks` before save; the layout stage and the save-stage figure check; parser version 16.
- `src/lib/parse/layout.ts` — the layout pass: the parse model reads the page's HTML digest beside the block list and answers index-based ops (roles, headings, joins, figure rows, drops, font).
- `src/lib/parse/figure-style.ts`, `src/lib/parse/figures.ts`, `src/lib/parse/sanitize.ts`, `src/lib/parse/figure-audit.ts`, `src/lib/parse/render-page.ts`, `src/lib/browser.ts`, `src/lib/video/browser-transcript.ts` — the page-style bake (hidden, alignment, weight, size, font, media widths), figure rows and caption repair, width and center in the stored html, the caption-vs-figure audit, the browser render for script-drawn charts, one shared browser launcher.
- `src/components/reader/reader.tsx`, `block-view.tsx`, `document-title.tsx`, `document-bar.tsx`, `reveal.tsx`, `reader-interactions.tsx`, `src/components/video/assistant-card.tsx`, `src/app/globals.css`, `src/app/api/documents/[documentId]/route.ts`, `src/lib/i18n/dict/reader.ts` — layout tokens rendered, the centered masthead, figure rows as a wrapping row honoring the page's widths, the `sans` document font and its menu option, the first-open reveal.

- `SPEC.md` — §2 (three passes, the layout bake), §6 (layout tokens, figure rows, fonts, first open), §8 Phase 2 and Phase 7, §15 (figure check, tab order).

**Decisions:**
- Layout travels as class tokens on a text block's opening tag (`<p class="kicker center">`) and as inline widths inside figure html, not as a new column: no migration, and the reader reads what it already stores.
- The mechanical walk and the layout pass produce the same tokens; the pass runs after the core and structure passes and never writes text (a join concatenates with one separator; a figure row wraps figures).
- A URL document's `font` is set once, at creation; a re-parse never changes a reader's font choice.
- The browser render runs only where `BROWSER_WS_ENDPOINT` or `CHROMIUM_PATH` is set (the §11 browser); without one the caption stays, the audit reports it, and the upload assistant says so.
- The glossary route translates existing definitions into the asked language with one call rather than rebuilding the glossary; terms are never translated.
- The `.next` symlink that the merge worktree had staged is untracked again.
